How a run works

Hand it work the way you'd hand it to a teammate

Four stages, every time. The last two are the reason contractors trust the first two.

01

You hand it work

Build this estimate. Enter this into the portal. Pull these numbers. Describe the task in plain language — the way it's actually assigned.

02

The agent executes

Atmosphere signs in and does the work — in your systems, in the carrier's, or on a real machine. Every step is recorded as it happens.

03

The Verifier checks

A second agent goes back and looks, in read-only. It confirms the work against the original task and flags anything it isn't sure of.

04

You hold the record

The run lands in the audit trail. Replay it step by step, or read it back like a receipt.

Security

Built like it handles your books — because it does

The shape of the system is the security model. These aren't policies; they're architecture.

auth

Passwords are never stored by us

Supabase Auth holds only a bcrypt hash in its secure users table. The application never sees or persists a plaintext password.

httpOnly

Tokens never touch browser JavaScript

Sessions live in httpOnly cookies set by the backend. Page JavaScript holds no tokens, which shuts the door on token theft via XSS.

RLS

The database decides who sees what

Every query runs under the caller's own identity, so Row-Level Security — not application code — enforces access. Another organization's data is invisible at the database layer.

Teams

One organization, every role

Create an organization or join with a code. Everyone linked to the org can see and communicate with everyone else — and every agent works on the org's behalf.
