Billing & the flat rate

The 30-day test, seat plans, and how the one flat token rate is set and metered.

The 30-day test

Every organization starts with thirty days of the full platform — no feature held back, one seat. Usage during the test is billed at the same flat rate as everyone else, so what you spend testing is what the thing would actually cost you. Nothing auto-upgrades when the thirty days end: you pick a plan, or you stop.

Seats

The seat price buys access and a throughput ceiling, nothing else:

All four platforms — Sales, Operations, Field, Manager — are bought separately at these same tiers.

The flat rate

Usage is billed per token at one rate, set by the most advanced model we run — Claude Opus 5 — at twice its list price:

Input   $30  per million tokens   (2 × $15 list)
Output  $150 per million tokens   (2 × $75 list)

Every token is billed at that rate whichever model actually ran the task. Because the rate never moves, routing work to a weaker model could only cost us quality — so the router picks the model that does the work best, not the one that protects a margin.

How usage is counted

Token counts come from the model provider's own response, never from the browser — what you are billed is what was actually spent. Every grant, charge, and adjustment lands in an append-only ledger you can read by run, by agent, and by platform.

There is no allowance

No bundled credits, nothing to run out of, nothing to waste. Agents spend tokens while they work, you are billed for exactly those, and a quiet week costs you the seat and nothing more.
