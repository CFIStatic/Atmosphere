Security

The shape of the system is the security model

Access control at Atmosphere isn't a policy we promise to enforce in application code. It's architecture: the database, the cookie jar, and the network direction do the enforcing — and they can't be talked out of it.

ARCHITECTURE PRINCIPLES VERIFICATION
Architecture

Every request wears the caller's identity

The browser talks to a backend-for-frontend. The backend talks to Postgres with the caller's own JWT — never a service-role key — so Row-Level Security decides what every query can see.

The frontend holds no tokens. The database enforces access. The operated machine only ever dials out.

Principles

Six things that are true by construction

Each of these holds because of where the data lives and which direction the wires point — not because a code path remembered to check.

bcrypt

Passwords are never stored by us

Supabase Auth stores only a bcrypt hash in the secure auth.users table. The app never sees or persists a plaintext password.

httpOnly

Tokens never touch browser JavaScript

The backend exchanges credentials for a session and puts the access and refresh tokens in httpOnly cookies. Page JavaScript holds nothing worth stealing, which mitigates token theft via XSS.

RLS

Row-Level Security is the source of truth

Every org query runs under the caller's JWT — never the service-role key. Who can see what is decided at the database layer, where cross-organization data simply doesn't exist for you.

device

PIN sign-in is bound to one device

The optional 4-digit PIN enrolls a single device, and the server keeps only hashes — no secret and no session token. A stolen PIN without the enrolled device is worthless.

server-side

Password recovery happens on the server

Reset links arrive by email, and the token exchange is performed on the server — so no Supabase token is ever exposed to page JavaScript, even during recovery.

outbound

The agent dials out, never in

A computer running the Atmosphere agent connects over an outbound-only WebSocket. No inbound port is opened on the machine being operated.

Verification

Trust is a workflow, not a checkbox

Work the AI does in someone else's system is checked afterwards by a second agent that goes and looks — in a read-only browser that cannot change anything. And everything every agent does lands in one append-only audit trail your organization can replay step by step.
